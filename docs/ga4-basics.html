01基礎GA4

GA4の基礎

GA4（Google アナリティクス 4）は「すべてをイベントとして記録する」計測ツールです。この章では、データがどんな形で記録され、どこで見られて、どんな制約があるかを押さえます。

データモデル: すべてはイベント

旧 Google アナリティクス（UA）は「ページビュー」「イベント」「トランザクション」など種類の違うヒットを記録していました。GA4 ではページビューもスクロールも購入も、すべて同じ形のイベントです。1つのイベントは次の要素でできています。

要素例（このリポジトリの index.html）誰が付けるか
イベント名button_click自分
イベントパラメータbutton_name: "資料ダウンロード", section: "hero"自分
自動で付くパラメータpage_location, page_title, ga_session_id, engagement_time_msecGA4（gtag.js）
ユーザープロパティplan: "pro", user_type: "returning"自分（一度セットすると以降のイベントに付く）
ユーザー識別子user_pseudo_id（自動）、user_id（任意）GA4 / 自分
端末・地域などブラウザ、OS、国、市区町村、流入元GA4 が自動で付与

index.html のボタンを押したときに実際に動いているコードはこれだけです。

gtag("event", "button_click", {
  button_name: "資料ダウンロード",
  section: "hero",
});
この章の一番大事なこと

送ったパラメータは GA4 に届いて保存されます。しかし GA4 の画面（レポートや探索）で使うには、カスタムディメンションとして登録する必要があります。BigQuery には登録しなくても全部入ります。この違いが次章以降のテーマです。

例外として、method・content_type・search_term など GA4 の既定ディメンションと同じ名前のパラメータは、登録なしで見えます。独自イベントで送っても同じです。

アカウント・プロパティ・データストリーム

アカウント（会社・組織の単位）         a235761773
└── プロパティ（分析の単位。レポートはここ） 324810718
    ├── データストリーム: ウェブ          測定ID G-FEHSK6QJLE
    ├── データストリーム: iOS アプリ      （このリポジトリでは未使用）
    └── データストリーム: Android アプリ
  • プロパティがレポート・カスタム定義・BigQuery リンクの単位です。サイトとアプリを1つのプロパティにまとめて分析できます。
  • 測定ID（G-）はウェブのデータストリームに付くIDで、タグに書くのはこれです。
  • プロパティID（数字）は API や BigQuery のデータセット名（analytics_324810718）で使います。

イベントの4分類

自分でコードを書かなくても多くのイベントが記録されます。何が自動で、何を自分で送るべきかを区別しておくと設計が楽になります。

分類代表例設定
自動収集イベントfirst_visit, session_start, user_engagementタグを入れるだけで記録
拡張計測機能page_view, scroll（90%到達）, click（外部リンク）, file_download, view_search_results, video_start, form_start, form_submit管理データの収集と修正データストリーム拡張計測機能 でオン・オフ
推奨イベントsign_up, login, view_item, add_to_cart, purchaseGoogle が名前とパラメータを決めている。自分で送る
カスタムイベントbutton_click, form_field_focus, user_switch名前もパラメータも自由。自分で送る
設計のコツ

推奨イベントに当てはまるものは、その名前とパラメータ名（value, currency, items など）で送ります。GA4 の既定のレポート（収益化など）が自動で埋まり、推奨のパラメータ名の値は登録なしでディメンションとして使えます。拡張計測と同じ名前（form_submit など）を自作イベントに使うと集計が混ざるので避けるのが無難です。

ディメンション・指標・スコープ

  • ディメンション: 切り口。文字列の属性。例: ページタイトル、デバイス、ボタン名。
  • 指標: 数値。例: イベント数、アクティブユーザー数、セッション数、収益。

レポートは「ディメンション × 指標」の表です。自分で送った値をディメンションや指標として使うときはスコープを選んで登録します。

スコープ元になる値値の持続例
イベントイベントパラメータそのイベント1件だけbutton_name, section
ユーザーユーザープロパティセット後のすべてのイベントplan, user_type
アイテムitems 配列の中のキーその商品行だけitem_color

セッションスコープのディメンション（参照元やランディングページ）は GA4 が用意したものだけで、自作はできません。

ユーザーとセッションの識別

3つのID

ID正体範囲
user_pseudo_idCookie _ga に入るブラウザ単位のID。自動同じブラウザの間だけ同一人物
user_id自分で送るログインIDなど端末やブラウザをまたいでまとめられる
Google シグナルGoogle アカウントにログイン中のユーザー情報有効にするとデモグラフィックなどが使えるが、しきい値（少人数の非表示）が出やすくなる

どのIDを優先してユーザーを数えるかは 管理データの表示レポート ID で選びます（「ハイブリッド」「計測データ」「デバイスベース」）。

セッション

セッションは「ひと続きの訪問」です。最後の操作から30分（既定）何もしないと切れます。各イベントには ga_session_id（セッション開始時刻）と ga_session_number（何回目の訪問か）が自動で付きます。BigQuery では user_pseudo_id と ga_session_id の組み合わせで1セッションを数えます（06章）。

このリポジトリでの実践: user_id と user_properties

index.html は仮ユーザーのUUIDを2通りの形で送っています。値は同じでも役割と使える場所が違います。

user_iduser_properties
正体GA4 の予約された識別子自作のユーザースコープ属性
設定作業管理データの表示レポート ID で有効化管理データの表示カスタム定義 に登録
レポートで絞り込みできないできる（比較・セグメント）
ユーザーエクスプローラできる（行が User-ID になる）—
BigQueryuser_id 列user_properties 列（ARRAY of STRUCT）
// user_properties は値が36文字までなので UUID がちょうど収まる
gtag("set", "user_properties", {
  app_user_id: uuid,
  plan: "pro",
  user_type: "returning",
});
gtag("config", "G-FEHSK6QJLE", { user_id: uuid });
  • IDを途中で切り替える場合: gtag('config') を再実行します。そのままだと page_view が重複送信されるので send_page_view: false を付けます。
  • debug_mode の注意: 公式ドキュメントには gtag('config', ID, {debug_mode: true}) で DebugView に出るとあります。実測すると現在の gtag.js は ep.debug_mode=true（ただのイベントパラメータ）として送るだけで、DebugView には現れませんでした。DebugView を使うときは Tag Assistant で接続するか、Chrome 拡張の Google Analytics Debugger を使います。

計測を実装する3つの方法

1. gtag.js を直書きする（index.html の方式）

すべてのページの <head> に次を入れます。gtag() は引数を dataLayer に積むだけの小さな関数で、読み込まれた gtag.js がそれを読んで送信します。

<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag() { dataLayer.push(arguments); }
  gtag("js", new Date());
  gtag("config", "G-XXXXXXXXXX");
</script>

カスタムイベントは gtag("event", イベント名, パラメータ) で送ります。

gtag("event", "button_click", { button_name: "購入ボタン" });

2. Google タグマネージャー（GTM）を使う（gtm.html の方式）

ページには GTM のコンテナを1つ入れるだけにして、「どのクリックで何を送るか」を GTM の管理画面で設定します。コードを変えずに計測を追加・修正できます。詳しくは 03・04章で扱います。

3. Measurement Protocol（サーバーから送る）

決済完了や解約など、サーバー側で確定する出来事を HTTP で直接 GA4 に送る方法です。管理データの収集と修正データストリームMeasurement Protocol API secret でシークレットを発行して使います。ブラウザ計測の補完として使うもので、このリポジトリでは扱いません。

二重計測に注意

gtag.js の直書きと、同じ測定IDの Google タグを入れた GTM を同じページに置くと、page_view などが2回ずつ送られます。どちらか一方に寄せます。このリポジトリでは index.html が gtag.js、gtm.html が GTM と、ページを分けています。

画面で数字が「おかしく」見える3つの理由

  • しきい値: 少人数のデータは個人が特定されないよう非表示になります。Google シグナル有効時に起きやすいです。
  • (other): 1日の行数が上限を超えると、値の種類が多いディメンション（UUIDなど）は (other) にまとめられます。
  • (not set): そのイベントにパラメータが付いていない行です。たとえば「ボタン名」で page_view を見ると (not set) になります。

覚えておくべき上限値

標準（無料）プロパティの主な上限です。超えた分は切り捨てや無視になり、エラーは出ないので、設計時に意識しておきます。

項目上限
イベント名の長さ40文字
1イベントあたりのパラメータ数25個
パラメータ名の長さ40文字
パラメータ値の長さ（page_location などを除く）100文字
ユーザープロパティ名 / 値の長さ24文字 / 36文字
イベントスコープのカスタムディメンション50個
ユーザースコープのカスタムディメンション25個
アイテムスコープのカスタムディメンション10個
カスタム指標50個
探索で使えるデータの保持期間2か月 or 14か月

データ保持期間は 管理データの収集と修正データ保持 で変えられます。既定は2か月なので、作ったらすぐ14か月に変えておくのがおすすめです。標準レポートの集計値はこの設定に関係なく残ります。カスタムディメンションを削除して枠を空けた場合、同じ枠を使えるのは48時間後です。
