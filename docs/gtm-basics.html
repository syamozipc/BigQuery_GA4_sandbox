03基礎GTM

GTMの基礎

Google タグマネージャー（GTM）は、計測のコードをページに書く代わりに、管理画面で設定できるようにするツールです。この章では、すでに知っている send-gtag.html の gtag コードと対応づけながら仕組みを理解します。

GTMで何が変わるか

ページに入れるのは、GTM のコンテナ（GTM-XXXXXXX）を読み込むスニペット1つだけです。「何を・いつ送るか」の設定はすべて GTM の画面で作り、「公開」を押すとサイトに反映されます。

gtag.js 直書き（send-gtag.html）GTM（send-gtm.html）
計測を足す・直すコードを修正してデプロイGTM の画面で設定して公開
動作の確認DebugView、開発者ツールプレビューで、どのタグが動いたかまで見える
元に戻すGit で戻してデプロイ公開した版（バージョン）を選んで戻す

タグ・トリガー・変数

GTM の設定は、すべて3つの部品の組み合わせです。「資料請求ボタンが押されたら、GA4 に cta_click を送る。ボタン名も付けて」という1つの指示を分解すると、こうなります。

部品指示のどこかこの例での中身
トリガー「〜されたら」資料請求ボタンが押されたとき
タグ「〜を送る」GA4 にイベント cta_click を送る
変数「〜も付けて」押されたボタンの名前（資料請求）

send-gtag.html のコードとの対応

GTM で GA4 を送る設定は、send-gtag.html の gtag コードを GTM の画面で作り直したものです。

send-gtag.html のコード役割GTM での部品
gtag("config", "G-FEHSK6QJLE")最初に1回だけ実行する初期設定。page_view もこれが送るGoogle タグ（トリガーは Initialization - All Pages）
gtag("event", "button_click", …)出来事のたびに送るGA4 イベントタグ
onclick="…"いつ送るかトリガー
{ button_name: "資料ダウンロード" }付ける値変数

GA4 イベントタグは、同じ測定IDの Google タグの設定を引き継ぎます。Google タグに付けたパラメータは、全イベントに付きます。

二重計測に注意

send-gtag.html のように gtag.js を直書きしたページに、同じ測定IDの Google タグを入れた GTM も置くと、全イベントが2回送られます。このリポジトリでは send-gtag.html が gtag.js、send-gtm.html が GTM と、ページを分けています。

dataLayer の仕組み

dataLayer はページ内のただの JavaScript 配列です。GTM はこの配列の push を監視していて、オブジェクトが積まれるたびに中身を読み取ります。

// GTM スニペットより前に置く（なければ GTM が作る）
window.dataLayer = window.dataLayer || [];

// event キーがあると「カスタムイベント」としてトリガーの判定が走る
dataLayer.push({
  event: "cta_click",
  cta_name: "資料請求",
  cta_position: "hero",
});

// event キーがない push は値の更新だけ。トリガーは動かない
dataLayer.push({ user_plan: "pro" });
  • event キーが合図です。カスタムイベントトリガーはこの値で一致を判定します。
  • GTM は push された値を内部の状態にマージして持ち続けます。前の push の値が残るので、ECデータのように毎回変わるオブジェクトは、先に { ecommerce: null } を push してリセットするのが定石です。
  • gtag.js も同じ dataLayer を使います（gtag() は arguments を push する関数）。だから GTM と gtag.js は同じページで干渉しやすいのです。

GTM 自身も、ページの読み込みやクリックのたびに gtm.js や gtm.click などのメッセージを積みます。一覧はページ末尾のリファレンスにあります。

2つの計測アプローチ

「dataLayer に push する方法」と「スクリプトだけ置いて、GTM の画面からクラス名などで制御する方法」の2つがあります。実務ではこの2つに、両者の中間の「data属性」を加えた3段階で考えると整理しやすいです。

A: dataLayer.pushB: クラス名・ID・テキストB': data属性
ページ側の作業出来事ごとに push を書くなし（既存のHTMLを使う）data-track-name="…" を足すだけ
GTM 側の設定カスタムイベント + データレイヤーの変数クリックトリガー + 組み込み変数クリックトリガー + 自動イベント変数
渡せる情報何でも（価格、商品配列、ログイン状態など画面にない値も）画面に出ている情報だけHTML に書ける値
デザイン改修への強さ強い。見た目と無関係弱い。クラス名や文言の変更で止まる比較的強い。属性を残せば動く
非同期の結果API 成功後など、確定した時点で送れる押した瞬間しか分からない。失敗も数える同左
向いているもの購入、会員登録、フォーム送信完了などの成果試しに測りたいボタン、外部リンク、検証UI 上のクリックを継続的に測る
使い分けの目安

お金や成果に関わるイベントは A（dataLayer）で、エンジニアとマーケ担当が「イベント名とパラメータの仕様書」を合意して実装します。UI のクリック計測は B'（data属性）にすると、改修で壊れにくく、GTM 側だけで足し引きできます。B（クラス名）は既存サイトにコードを触らず計測を足したいときの手段で、壊れやすいと割り切って使います。

04章では、練習用ページ send-gtm.html で A・B・B' をすべて設定し、「クラス名を変えると B だけが止まる」ことを実際に確かめます。

編集から公開までの流れ

  1. ワークスペースで編集

    タグ・トリガー・変数を作ります。この時点ではまだ本番に反映されていません。

  2. プレビューで確認

    右上の「プレビュー」で Tag Assistant が開き、自分のブラウザだけに編集中の設定が適用されます。dataLayer の中身、各メッセージで配信されたタグ・未配信のタグ、変数の値が見られます。設定を変えたら、プレビューを接続し直します。

  3. 公開

    「公開」を押し、バージョン名と説明（何を変えたか）を書いて公開します。全訪問者に反映されます。

  4. 必要なら切り戻し

    バージョン から過去の版を選んで「公開」すれば元に戻ります。

よくある落とし穴

  • 二重計測: gtag.js 直書きと GTM の Google タグを同じ測定IDで併用すると、全イベントが2回送られます。
  • 子要素のクリック: ボタンの中のアイコンや <span> を押すと、Click Element はその子要素になります。CSS セレクタは .btn, .btn * のように子孫も含めます。
  • フォームの妥当性チェック: ページ側で preventDefault() しているフォームは、フォーム送信トリガーの「妥当性をチェック」をオンにすると発火しません。
  • SPA: React などで URL だけ変わる画面遷移は、ページビュートリガーでは拾えません。履歴の変更トリガーか、遷移時の push で対応します。
  • 公開し忘れ: プレビューで動いても、公開しなければ本番のユーザーには何も起きません。
  • 同意（Consent）: EU 向けなどで同意バナーを出す場合は、同意モードの設定と「Consent Initialization」トリガーが関わります。このリポジトリでは扱いません。

GTM は読み込み時やクリック時に、自分でも dataLayer にメッセージを積みます。プレビューモードの左側に並ぶのがこれです。
