GTMを実際に使う

練習用ページ gtm.html を使って、方式A（dataLayer.push）と方式B（クラス名・data属性）の両方で GA4 にイベントを送ります。最後に「クラス名を変えると方式Bだけ止まる」ことを確かめ、公開まで行います。所要時間は60〜90分です。

ページの見方

gtm.html の右側には dataLayer の中身が新しい順に表示されます。ボタンを押したときに何が積まれたかを見ながら進めると、GTM の動きがよく分かります。青枠がページのコードが積んだもの、灰色が GTM 自身が積んだもの（gtm.*）です。(event なし) は event キーのない push で、トリガーは動きません。

準備: コンテナと Google タグ

  1. GTM のアカウントとコンテナを作る

    tagmanager.google.com で「アカウントを作成」を押し、次のように入力します。

    アカウント名sandbox など自由
    国日本
    コンテナ名syamozipc.github.io
    ターゲット プラットフォームウェブ

    利用規約に同意するとインストール用のスニペットが表示されます。gtm.html にはすでに組み込んであるので、閉じて構いません。画面上部に表示される GTM-XXXXXXX がコンテナIDです。

    GTM- は設定を入れる箱（コンテナ）のID、G- は GA4 の送り先（測定ID）で、まったく別物です。GTM の箱の中に Google タグを作り、そのタグが G- に送ります。

  2. gtm.html にコンテナIDを設定する

    gtm.html の window.GTM_ID と、<body> 直後の noscript にある id= の2か所を、自分のコンテナIDに書き換えます。このリポジトリでは GTM-KXV4CBBD を設定済みです。

    gtm.html を開き、「GTM-KXV4CBBD 読み込み済み」と表示され、右の dataLayer に gtm.js・gtm.dom・gtm.load が並べば成功です。ローカルで試すときは、リポジトリ直下で python3 -m http.server 8000 を実行し、http://localhost:8000/gtm.html を開きます。

  3. Google タグを作る

    タグ新規タグの設定Google タグ を選びます。

    タグ名GA4 - Google タグ
    タグ IDG-FEHSK6QJLE
    共有イベントの設定「イベントの設定変数」は「なし」のまま、「パラメータを追加」で tag_source = gtm
    全イベントに付く。index.html（gtag.js）から来たデータと見分けるため
    トリガーInitialization - All Pages

    このタグだけで page_view などの自動イベントが送られるようになります。

  4. プレビューで接続する

    GTM 画面右上の「プレビュー」を押すと Tag Assistant が開きます。gtm.html のURLを入れて「Connect」を押すと、別ウィンドウで gtm.html が開き、右下に「Tag Assistant Connected」と出ます。ボタンは、この接続で開いた gtm.html で押します。

    Tag Assistant の画面の見方です。

    • 上部のタブ: GTM-KXV4CBBD は GTM の動き（どのタグが動いたか）、G-FEHSK6QJLE は GA4 に実際に送った内容です。
    • 左の一覧: dataLayer に積まれたメッセージが新しい順に並びます。「同意の初期化」「初期化」「コンテナの読み込み」「DOM Ready」「ウィンドウの読み込み」は GTM が自分で積むもので、ボタンを押すと cta_click などが上に増えます。
    • 右側: 選んだメッセージについて、タグ・変数・データレイヤーのタブで中身が見られます。

    左の一覧で「初期化」を選ぶと、「配信されたタグ」に「GA4 - Google タグ」が出ています。

    GA4 に届いたかは、レポートリアルタイムの概要 の「イベント数（イベント名）」カードで確かめます。page_view を押し、パラメータの一覧から tag_source を開いて値が gtm なら GTM 経由です。パラメータはアルファベット順なので、tag_source は一覧の下の方にあります。

    設定を変えたら接続し直す

    プレビューは、接続した時点の設定で動きます。GTM で何かを保存したら、必ずもう一度「プレビュー」を押して接続し直してください。忘れると、新しいタグが「未配信」のまま、パラメータも付かないままになります。

方式A: dataLayer.push

gtm.html の「資料請求」ボタンは、押すと次の1行を実行します。GTM 側では「event が cta_click のメッセージが来たら、その中の cta_name と cta_position を GA4 に送る」設定を作ります。

dataLayer.push({ event: "cta_click", cta_name: "資料請求", cta_position: "hero" });

dataLayer は、ページから GTM への「連絡メモを入れる箱」です。ページは「何が起きたか」をメモに書くだけで、GA4 のことは知りません。GTM がメモを読み、どこに何を送るかを決めます。

メモの項目GTM での使われ方
event: "cta_click"何が起きたか。トリガーがこの値でルールを選ぶ
cta_name, cta_position付け足しの情報。変数で読み出してタグに渡す
設定前に一度押してみる

何も設定していない状態で「資料請求」を押すと、Tag Assistant の左の一覧に cta_click は増えますが、「配信されたタグ」は「なし」です。GTM はメモを受け取っても、トリガーとタグがなければ GA4 に何も送りません。設定後と見比べると違いが分かります。

  1. データレイヤーの変数を作る

    変数ユーザー定義変数新規データレイヤーの変数 を2つ作ります。

    変数名データレイヤーの変数名データレイヤーのバージョン
    dlv - cta_namecta_nameバージョン 2
    dlv - cta_positioncta_positionバージョン 2

    ネストした値は ecommerce.value のようにドット区切りで取り出せます。

  2. カスタムイベントのトリガーを作る

    トリガー新規カスタム イベント

    トリガー名CE - cta_click
    イベント名cta_click
    push した event の値と完全一致
    このトリガーの発生場所すべてのカスタム イベント

  3. GA4 イベントタグを作る

    タグ新規Google アナリティクスGoogle アナリティクス: GA4 イベント

    タグ名GA4 - cta_click
    測定 IDG-FEHSK6QJLE
    イベント名cta_click
    イベント パラメータcta_name = {{dlv - cta_name}}
    cta_position = {{dlv - cta_position}}
    トリガーCE - cta_click

    値の欄の右にあるブロックのアイコンを押すと、変数を一覧から選べます。

  4. プレビューで確かめる

    プレビューを接続し直し、gtm.html で「資料請求」を押します。Tag Assistant の左に cta_click が増えるので選びます。

    • タグタブ: 「GA4 - cta_click」が「配信されたタグ」にある。
    • 変数タブ: dlv - cta_name が「資料請求」、dlv - cta_position が「hero」になっている。
    • データレイヤータブ: push したオブジェクトがそのまま見える。

    変数のタイプやタグのタイプが「不明な変数タイプ」「不明なタグタイプ」と表示されることがありますが、値が正しく取れていれば問題ありません。「未配信のタグ」に別のタグが並ぶのも正常です。そのメッセージでは発火しない、別のトリガーのタグだからです。

    「無料で始める」を押すと、同じタグが cta_position = footer で発火します。タグを1つ作れば、push する値を変えるだけで使い回せるのが方式Aの強みです。

  5. 練習: sign_up を自分で作る

    「会員登録する」ボタンは 0.8 秒待ってから { event: "sign_up", method: "email" } を push します。本物のサイトでは API が成功した後に push する、という想定です。これまでと同じ手順で、変数 dlv - method、トリガー CE - sign_up、タグ GA4 - sign_up（パラメータ method）を作ってみてください。

    method は GA4 の既定ディメンション「方法」なので、カスタムディメンションに登録しなくても GA4 で見られます。

  6. e コマースのデータを送る

    「プロプランをカートに追加」ボタンは、GA4 推奨の形で ecommerce オブジェクトを push します。この形なら、パラメータを1つずつ変数にしなくても、タグの設定だけで丸ごと送れます。

    トリガーCE - add_to_cart（カスタム イベント、イベント名 add_to_cart）
    タグGA4 イベント、イベント名 add_to_cart
    その他の設定 › e コマース「e コマースデータを送信」にチェック。その下に出る「データソース」は「Data Layer」

    GA4 イベントタグが送るのは、基本的に「イベント パラメータ」の欄に書いたものだけです。チェックを入れると、dataLayer の最新の ecommerce を丸ごと読み、currency・value・items を送ります。チェックを忘れると、イベントは届くのに金額と商品の情報が空になります。データソースのもう1つの選択肢「変数」は、dataLayer が推奨の形でないサイトで、変数で組み立てたオブジェクトを渡すときに使います。

    保存してプレビューを接続し直し、「プロプランをカートに追加」を押して確かめます。

    • GTM-KXV4CBBD のタブ: add_to_cart で「GA4 - add_to_cart」が配信されている。
    • G-FEHSK6QJLE のタブ: add_to_cart の送信内容に items が入っている。チェックの効果はここでしか見分けられません。

    BigQuery では items 列（配列）に商品の情報が入ります（06章）。

実務での省力化

ここでは仕組みを理解するためにイベントごとにタグを作りましたが、実務ではタグを使い回すのが普通です。イベント名に {{Event}} を入れた GA4 イベントタグを1つ作り、トリガーはカスタムイベントで「正規表現一致を使用」にして ^(cta_click|sign_up)$ のように複数の名前に反応させます。新しいイベントを足すときは、ページの push と正規表現への追記だけで済みます。

方式B: クラス名・data属性

gtm.html の「方式B」のボタンには計測のコードがありません。HTML はこれだけです。

<button class="js-track-click" data-track-name="pricing_pro">
  <span class="icon">▶</span> プロプランを見る
</button>

GTM の「クリック」トリガーにページ全体のクリックを監視させ、押された要素がこのクラスを持っていたら発火させます。

  1. 組み込み変数を有効にする

    変数組み込み変数設定 を開き、「クリック」の Click Element、Click Classes、Click ID、Click Text、Click URL にチェックを入れます。

  2. クラス名で判定するトリガーを作る

    トリガー新規クリック - すべての要素

    トリガー名Click - class
    このトリガーの発生場所一部のクリック
    条件Click Element ／ CSS セレクタに一致する ／ .js-track-click, .js-track-click *

    後半の .js-track-click * は「その中の子要素」の意味です。ボタンの中の ▶ アイコンを押すと、押された要素は <span class="icon"> になるため、これがないと取りこぼします。

    条件を Click Classes 含む js-track-click にする書き方もよく見かけます。簡単ですが、子要素を押したときは発火しません。

  3. 押された要素の名前を取る変数を作る

    どのボタンが押されたかは data-track-name 属性で区別します。子要素を押した場合にも対応するため、親をたどって属性を探すカスタム JavaScript 変数を作ります。この変数は、次の手順でタグのパラメータに {{cjs - track name}} と書いたときに紐づき、タグが発火するたびに実行されます。

    変数ユーザー定義変数新規カスタム JavaScript、変数名は cjs - track name です。

    function () {
  var el = {{Click Element}};
  var target = el && el.closest ? el.closest("[data-track-name]") : null;
  return target ? target.getAttribute("data-track-name") : undefined;
}
    もっと簡単な「自動イベント変数」との違い

    自動イベント変数変数タイプ: 要素の属性属性名: data-track-name でも同じ値が取れます。ただしこれは押された要素そのものの属性しか見ないので、▶ アイコンを押したときは空になります。ボタンの中に子要素がないサイトならこちらで十分です。

  4. GA4 イベントタグを作る

    タグ新規Google アナリティクス: GA4 イベント

    タグ名GA4 - ui_click
    測定 IDG-FEHSK6QJLE
    イベント名ui_click
    イベント パラメータclick_name = {{cjs - track name}}
    click_text = {{Click Text}}
    click_url = {{Click URL}}
    トリガーClick - class

  5. プレビューで確かめる

    接続し直して「プロプランを見る」を押します。gtm.html の右側に gtm.click が現れ、gtm.element に押された要素（<button.js-track-click[data-track-name="pricing_pro"]>）が入っているのが見えます。Tag Assistant では左の一覧の「クリック」で「GA4 - ui_click」が配信され、cjs - track name が pricing_pro になっています。

    ▶ アイコンの部分を狙って押しても同じ結果になることも確かめてください。

観察ポイント

クリックトリガーを作る前は、ボタンを押しても dataLayer に gtm.click は出ません。GTM は、クリックトリガーが1つでもあるときだけクリックを監視します。

壊れ方を比べる

方式Bの弱点は「見た目のための名前に計測が依存する」ことです。デザイン改修でクラス名が変わったときに何が起きるかを試します。

  1. クラス名を変えて押す

    gtm.html の「デザイン改修をシミュレート（クラス名を変更）」をオンにします。ボタンのクラスが js-track-click から btn-cta-v2 に変わります。この状態で「プロプランを見る」を押すと、gtm.click は出ますが、Tag Assistant では「GA4 - ui_click」が 未配信のタグ に移ります。エラーはどこにも出ません。

    一方、方式Aの「資料請求」は変わらず発火します。push のコードは見た目と関係ないからです。

  2. data属性で判定するトリガーに替える

    トリガー「Click - class」を開き、右上のメニューから「コピーを作成」します。名前を Click - data-attr に、条件の CSS セレクタを次に変えます。

    [data-track-name], [data-track-name] *

    タグ「GA4 - ui_click」のトリガーを Click - data-attr に差し替えて、プレビューを接続し直します。クラス名を変えたままでもタグが発火するようになります。

    確かめ終わったら、gtm.html のスイッチをオフに戻しておきます。

ここで分かったこと
  • 方式Aは壊れにくいが、計測を増やすたびにコードの変更が要る。
  • 方式Bはコードを触らずに足せるが、クラス名や文言の変更で黙って止まる。
  • data属性は「計測のための名前」をHTMLに残す約束なので、デザインの変更から切り離せる。チームで「data-track-name は消さない」と決めておく。

公開して GA4 で確認する

  1. 公開する

    右上の「公開」を押し、バージョン名と説明を書いて公開します。これでプレビューに接続していない普通の訪問でもタグが動きます。

    バージョン名v1 初期設定（Google タグと04章の練習用イベント）
    一覧で見分けるために短く。2回目以降は v2 ui_click に click_url を追加 のように、その版で変えたことを書く
    説明Google タグ（tag_source=gtm）
    方式A: cta_click / sign_up / add_to_cart
    方式B: ui_click（data属性で判定）
    発展: generate_lead / view_promotion

    公開した版は バージョン に残り、いつでも前の版に戻せます。

  2. GA4 のリアルタイムで確かめる

    Tag Assistant のタブを閉じ、プレビューに接続していない普通のタブで gtm.html を開いて各ボタンを押します。GA4 のリアルタイムの「イベント数（イベント名）」に cta_click、sign_up、add_to_cart、ui_click、generate_lead、view_promotion が出ます。cta_click を押すと、パラメータに cta_name と tag_source が見えます。

    出てこないときは、次の順に確かめます。

    • カードの下に隠れていないか。件数の多い順に並ぶので、下までスクロールするか次のページを見る。
    • ブラウザから送れているか。開発者ツールの「ネットワーク」で collect と絞り込み、en=cta_click を含むリクエストが出ているか見る。出ていなければ広告ブロッカーなどが止めている。
    • 公開できているか。GTM の「バージョン」に今回の版があり、「公開中」になっているか見る。

  3. カスタムディメンションを登録する

    02章と同じ手順で、管理データの表示カスタム定義 の「カスタム ディメンションを作成」から次の4つを登録します。範囲はすべて「イベント」です。

    ディメンション名イベント パラメータ説明
    CTA名cta_namecta_click で押された CTA ボタンの名前（資料請求 など）
    CTA位置cta_positioncta_click のボタンが置かれている場所（hero / footer）
    クリック名click_nameui_click で押された要素の data-track-name（pricing_pro など）
    タグの出どころtag_sourceGTM 経由のイベントに付く値（gtm）。gtag.js 直書きの index.html では空

    ディメンション名は必須で、日本語でかまいません。イベント パラメータはコードのキーと完全一致させます。method と form_id は登録が要りません。method は既定ディメンション、form_id は02章で登録済みです。

    翌日以降、探索で「タグの出どころ × イベント名」の表を作ると、gtag.js 経由と GTM 経由のデータを見分けられます。

  4. BigQuery で確かめる

    BigQuery では登録しなくてもすべてのパラメータが見えます。06章のレシピ「gtag.js と GTM の比較」で、tag_source ごとのイベント数を数えます。

    エクスポートの頻度見られる時期テーブル
    ストリーミング（有料）当日。送信から数分後events_intraday_YYYYMMDD
    毎日（無料）翌日events_YYYYMMDD

    当日分は、06章のレシピ9のように events_intraday_* を指定します。「does not match any table」と出たらストリーミングがオフなので、翌日を待つか、管理サービス間のリンク設定BigQuery のリンク で頻度に「ストリーミング」を加えます。画面上部の検索欄に「BigQuery」と入れても開けます。
