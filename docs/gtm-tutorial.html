GTMを実際に使う

練習用ページ gtm.html を使って、方式A（dataLayer.push）と方式B（クラス名・data属性）の両方で GA4 にイベントを送ります。最後に「クラス名を変えると方式Bだけ止まる」ことを確かめ、公開まで行います。所要時間は60〜90分です。

ページの見方

gtm.html の右側には dataLayer の中身が新しい順に表示されます。ボタンを押したときに何が積まれたかを見ながら進めると、GTM の動きがよく分かります。青枠がページのコードが積んだもの、灰色が GTM 自身が積んだもの（gtm.*）です。

準備: コンテナと Google タグ

  1. GTM のアカウントとコンテナを作る

    tagmanager.google.com で「アカウントを作成」を押し、次のように入力します。

    アカウント名sandbox など自由
    国日本
    コンテナ名syamozipc.github.io
    ターゲット プラットフォームウェブ

    利用規約に同意するとインストール用のスニペットが表示されます。gtm.html にはすでに組み込んであるので、閉じて構いません。画面上部に表示される GTM-XXXXXXX がコンテナIDです。

  2. gtm.html にコンテナIDを設定する

    gtm.html の window.GTM_ID と、<body> 直後の noscript にある id= の2か所を、自分のコンテナIDに書き換えます。このリポジトリでは GTM-KXV4CBBD を設定済みです。

    gtm.html を開き、「GTM-KXV4CBBD 読み込み済み」と表示され、右の dataLayer に gtm.js・gtm.dom・gtm.load が並べば成功です。ローカルで試すときは、リポジトリ直下で python3 -m http.server 8000 を実行し、http://localhost:8000/gtm.html を開きます。

  3. Google タグを作る

    タグ新規タグの設定Google タグ を選びます。

    タグ名GA4 - Google タグ
    タグ IDG-FEHSK6QJLE
    共有イベント設定 › イベント パラメータtag_source = gtm
    全イベントに付く。index.html（gtag.js）から来たデータと BigQuery で見分けるため
    トリガーInitialization - All Pages

    このタグだけで page_view などの自動イベントが送られるようになります。

  4. プレビューで接続する

    GTM 画面右上の「プレビュー」を押すと Tag Assistant が開きます。gtm.html のURLを入れて「Connect」を押すと、別ウィンドウで gtm.html が開き、右下に「Tag Assistant Connected」と出ます。

    Tag Assistant のタブに戻り、左の一覧で「Initialization」を選ぶと、Tags Fired に「GA4 - Google タグ」が出ています。GA4 のリアルタイムにも page_view が届きます。

    以降、GTM で設定を変えたら、もう一度「プレビュー」を押して接続し直すと最新の設定で試せます。

方式A: dataLayer.push

gtm.html の「資料請求」ボタンは、押すと次の1行を実行します。GTM 側では「event が cta_click のメッセージが来たら、その中の cta_name と cta_position を GA4 に送る」設定を作ります。

dataLayer.push({ event: "cta_click", cta_name: "資料請求", cta_position: "hero" });

  1. データレイヤーの変数を作る

    変数ユーザー定義変数新規データレイヤーの変数 を2つ作ります。

    変数名データレイヤーの変数名データレイヤーのバージョン
    dlv - cta_namecta_nameバージョン 2
    dlv - cta_positioncta_positionバージョン 2

    ネストした値は ecommerce.value のようにドット区切りで取り出せます。

  2. カスタムイベントのトリガーを作る

    トリガー新規カスタム イベント

    トリガー名CE - cta_click
    イベント名cta_click
    push した event の値と完全一致
    このトリガーの発生場所すべてのカスタム イベント

  3. GA4 イベントタグを作る

    タグ新規Google アナリティクスGoogle アナリティクス: GA4 イベント

    タグ名GA4 - cta_click
    測定 IDG-FEHSK6QJLE
    イベント名cta_click
    イベント パラメータcta_name = {{dlv - cta_name}}
    cta_position = {{dlv - cta_position}}
    トリガーCE - cta_click

    値の欄の右にあるブロックのアイコンを押すと、変数を一覧から選べます。

  4. プレビューで確かめる

    プレビューを接続し直し、gtm.html で「資料請求」を押します。Tag Assistant の左に cta_click が増えるので選びます。

    • Tags タブ: 「GA4 - cta_click」が Tags Fired にある。
    • Variables タブ: dlv - cta_name が「資料請求」になっている。
    • Data Layer タブ: push したオブジェクトがそのまま見える。

    「無料で始める」を押すと、同じタグが cta_position = footer で発火します。タグを1つ作れば、push する値を変えるだけで使い回せるのが方式Aの強みです。

  5. 練習: sign_up を自分で作る

    「会員登録する」ボタンは 0.8 秒待ってから { event: "sign_up", method: "email" } を push します。本物のサイトでは API が成功した後に push する、という想定です。これまでと同じ手順で、変数 dlv - method、トリガー CE - sign_up、タグ GA4 - sign_up（パラメータ method）を作ってみてください。

  6. e コマースのデータを送る

    「プロプランをカートに追加」ボタンは、GA4 推奨の形で ecommerce オブジェクトを push します。この形なら、パラメータを1つずつ変数にしなくても、タグの設定だけで丸ごと送れます。

    トリガーCE - add_to_cart（カスタム イベント、イベント名 add_to_cart）
    タグGA4 イベント、イベント名 add_to_cart
    その他の設定「e コマースデータを送信」にチェック、データソースは「Data Layer」

    BigQuery では items 列（配列）に商品の情報が入ります（06章）。

方式B: クラス名・data属性

gtm.html の「方式B」のボタンには計測のコードがありません。HTML はこれだけです。

<button class="js-track-click" data-track-name="pricing_pro">
  <span class="icon">▶</span> プロプランを見る
</button>

GTM の「クリック」トリガーにページ全体のクリックを監視させ、押された要素がこのクラスを持っていたら発火させます。

  1. 組み込み変数を有効にする

    変数組み込み変数設定 を開き、「クリック」の Click Element、Click Classes、Click ID、Click Text、Click URL にチェックを入れます。

  2. クラス名で判定するトリガーを作る

    トリガー新規クリック - すべての要素

    トリガー名Click - class
    このトリガーの発生場所一部のクリック
    条件Click Element ／ CSS セレクタに一致する ／ .js-track-click, .js-track-click *

    後半の .js-track-click * は「その中の子要素」の意味です。ボタンの中の ▶ アイコンを押すと、押された要素は <span class="icon"> になるため、これがないと取りこぼします。

    条件を Click Classes 含む js-track-click にする書き方もよく見かけます。簡単ですが、子要素を押したときは発火しません。

  3. 押された要素の名前を取る変数を作る

    どのボタンが押されたかは data-track-name 属性で区別します。子要素を押した場合にも対応するため、親をたどって属性を探すカスタム JavaScript 変数を作ります。

    変数ユーザー定義変数新規カスタム JavaScript、変数名は cjs - track name です。

    function () {
  var el = {{Click Element}};
  var target = el && el.closest ? el.closest("[data-track-name]") : null;
  return target ? target.getAttribute("data-track-name") : undefined;
}
    もっと簡単な「自動イベント変数」との違い

    自動イベント変数変数タイプ: 要素の属性属性名: data-track-name でも同じ値が取れます。ただしこれは押された要素そのものの属性しか見ないので、▶ アイコンを押したときは空になります。ボタンの中に子要素がないサイトならこちらで十分です。

  4. GA4 イベントタグを作る

    タグ名GA4 - ui_click
    測定 IDG-FEHSK6QJLE
    イベント名ui_click
    イベント パラメータclick_name = {{cjs - track name}}
    click_text = {{Click Text}}
    click_url = {{Click URL}}
    トリガーClick - class

  5. プレビューで確かめる

    接続し直して「プロプランを見る」を押します。gtm.html の右側に gtm.click が現れ、gtm.element に押された要素（<button.js-track-click[data-track-name="pricing_pro"]>）が入っているのが見えます。Tag Assistant ではこの Click で「GA4 - ui_click」が発火し、cjs - track name が pricing_pro になっています。

    ▶ アイコンの部分を狙って押しても同じ結果になることも確かめてください。

観察ポイント

クリックトリガーを作る前は、ボタンを押しても dataLayer に gtm.click は出ません。GTM は、クリックトリガーが1つでもあるときだけクリックを監視します。

壊れ方を比べる

方式Bの弱点は「見た目のための名前に計測が依存する」ことです。デザイン改修でクラス名が変わったときに何が起きるかを試します。

  1. クラス名を変えて押す

    gtm.html の「デザイン改修をシミュレート（クラス名を変更）」をオンにします。ボタンのクラスが js-track-click から btn-cta-v2 に変わります。この状態で「プロプランを見る」を押すと、gtm.click は出ますが、Tag Assistant では「GA4 - ui_click」が Tags Not Fired に移ります。エラーはどこにも出ません。

    一方、方式Aの「資料請求」は変わらず発火します。push のコードは見た目と関係ないからです。

  2. data属性で判定するトリガーに替える

    トリガー「Click - class」を開き、右上のメニューから「コピーを作成」します。名前を Click - data-attr に、条件の CSS セレクタを次に変えます。

    [data-track-name], [data-track-name] *

    タグ「GA4 - ui_click」のトリガーを Click - data-attr に差し替えて、プレビューを接続し直します。クラス名を変えたままでもタグが発火するようになります。

ここで分かったこと
  • 方式Aは壊れにくいが、計測を増やすたびにコードの変更が要る。
  • 方式Bはコードを触らずに足せるが、クラス名や文言の変更で黙って止まる。
  • data属性は「計測のための名前」をHTMLに残す約束なので、デザインの変更から切り離せる。チームで「data-track-name は消さない」と決めておく。

発展: フォームと要素の表示

  1. フォーム送信を計測する

    組み込み変数設定 で「フォーム」の Form ID を有効にしてから、トリガーを作ります。

    トリガーフォームの送信。名前 Form - gtm-form
    タグの配信を待つ / 妥当性をチェックどちらもオフ
    gtm.html は送信を preventDefault() で止めているため、「妥当性をチェック」がオンだと発火しない
    発生場所一部のフォーム ／ Form ID 等しい gtm-form
    タグGA4 イベント generate_lead（推奨イベント）、パラメータ form_id = {{Form ID}}

  2. バナーの表示を計測する

    gtm.html の下の方にある緑のバナー（id="promo-banner"）が画面に入ったときに送ります。

    トリガー要素の表示。名前 Vis - promo-banner
    選択方法CSS セレクタ #promo-banner
    このトリガーを起動するタイミング1ページにつき1度
    最小表示率50%
    変数自動イベント変数（要素の属性 data-promo-name）。名前 aev - promo name
    タグGA4 イベント view_promotion、パラメータ promotion_name = {{aev - promo name}}

    ここではバナーそのものに属性があるので、自動イベント変数で足ります。

公開して GA4 で確認する

  1. 公開する

    右上の「公開」を押し、バージョン名（例: v1 cta_click / ui_click / ecommerce）と、何を追加したかの説明を書いて公開します。これでプレビューに接続していない普通の訪問でもタグが動きます。

    公開した版は バージョン に残り、いつでも前の版に戻せます。

  2. GA4 のリアルタイムで確かめる

    プレビューを切った状態で gtm.html を開き、各ボタンを押します。GA4 のリアルタイムの「イベント数（イベント名）」に cta_click、ui_click、add_to_cart が出ます。cta_click を押すと、パラメータに cta_name と tag_source が見えるはずです。

  3. カスタムディメンションを登録する

    02章と同じ手順で、イベントスコープの cta_name、cta_position、click_name、tag_source を登録します。翌日以降、探索で「タグの出どころ（tag_source） × イベント名」の表を作ると、gtag.js 経由と GTM 経由のデータを見分けられます。

  4. 翌日 BigQuery で確かめる

    BigQuery では登録しなくてもすべてのパラメータが見えます。06章のレシピ「gtag.js と GTM の比較」で、tag_source ごとのイベント数を数えます。
