02ハンズオンGA4

カスタムディメンションを画面で見る

テストサイトが送っている button_name や plan を、GA4 のリアルタイム・探索・標準レポートで使えるようにします。所要時間は操作だけなら30分ほどです。探索と標準レポートでの確認は翌日以降になります。

なぜ登録が必要か

つまり「送る」と「登録する」は別作業です。新しいパラメータを実装したら、同じタイミングで GA4 側にも登録するのを習慣にします。

ただし method など既定ディメンションと同じ名前のパラメータは、登録しなくても見えます。

送っているパラメータの棚卸し

index.html のソースから、自分で送っている値を拾い出すとこうなります。登録するスコープもここで決めておきます。

キー種類例送っているイベント登録するスコープ
button_nameイベントパラメータ資料ダウンロードbutton_clickイベント
sectionイベントパラメータherobutton_clickイベント
item_nameイベントパラメータプロプランview_item, add_to_cartイベント
form_id / field_nameイベントパラメータcontact / emailform_field_focus, form_submitイベント
methodイベントパラメータemailsign_up不要（既定ディメンション「方法」）
priceイベントパラメータ（数値）8000view_item, add_to_cartカスタム指標（任意）
planユーザープロパティpro全イベントユーザー
user_typeユーザープロパティreturning全イベントユーザー
app_user_idユーザープロパティ（イベントパラメータにも同じ値）2222…2222全イベントユーザー
user_patternユーザープロパティ（イベントパラメータにも同じ値）b全イベントユーザー
補足

realtime.html は customUser:app_user_id と customUser:user_pattern を Data API で参照しています。これはこの2つがユーザースコープで登録済みであることが前提です（07章）。

イベントを送って届いたか確かめる

  1. テストサイトで操作する

    テストサイトを開き、仮ユーザーで「B: 有料プラン / リピーター」を選びます。「資料ダウンロード」を3回、「商品一覧」タブで「プロプラン 詳細」を2回押します。

  2. リアルタイムで生のパラメータを見る

    レポートリアルタイムの概要 の「イベント数（イベント名）」カードで、イベント名、パラメータ名の順に押すと値が出ます。登録前でも見られます。

    • button_click › button_name → 資料ダウンロード
    • view_item › item_name → プロプラン

  3. （任意）DebugView で1件ずつ見る

    Tag Assistant を開いて「ドメインを追加」にテストサイトのURLを入れ、接続します。開いたタブで操作すると、管理データの表示DebugView に端末が現れ、イベントごとのパラメータとユーザープロパティが時系列で見られます。

カスタムディメンションを登録する

場所は 管理データの表示カスタム定義 の「カスタム ディメンション」タブです。登録には編集者以上の権限が必要です。

  1. イベントスコープ: ボタン名

    「カスタム ディメンションを作成」を押し、次のように入力して保存します。

    ディメンション名ボタン名
    画面に表示される名前。日本語でよい
    範囲イベント
    説明button_click で押されたボタンの名前
    イベント パラメータbutton_name
    コードのキーと完全一致。大文字小文字も区別される。届いた実績があれば候補に出る

  2. イベントスコープ: 残りのパラメータ

    同じ手順で、範囲は「イベント」のまま次の4つを登録します。

    ディメンション名イベント パラメータ説明
    セクションsectionbutton_click のボタンが置かれている場所（hero など）
    商品名item_nameview_item / add_to_cart の商品名
    フォームIDform_idフォームの識別子（contact）
    入力欄field_nameform_field_focus でフォーカスした入力欄（name / email / message）

  3. ユーザースコープ: プランなど

    「範囲」をユーザーにすると、入力欄が「ユーザー プロパティ」に変わります。次の4つを登録します。

    ディメンション名ユーザー プロパティ説明
    プランplan契約プラン（free / pro / enterprise / churned）
    ユーザー種別user_typeユーザーの状態（new / returning / lead / dormant / anonymous）
    アプリユーザーIDapp_user_id自社サービスのユーザーID（UUID）
    ユーザーパターンuser_patternテストサイトの仮ユーザーのパターン（a〜d / random）

  4. （任意）カスタム指標: 価格

    「カスタム指標」タブで「カスタム指標を作成」を押します。指標名「価格」、範囲「イベント」、イベントパラメータ price、測定単位「通貨」にすると、探索で合計や平均が出せます。数値として送っているパラメータだけが指標にできます。

登録の注意
  • 登録は過去にさかのぼりません。登録後にもう一度テストサイトで操作しておくと、翌日の確認がスムーズです。
  • app_user_id と user_pattern はイベントパラメータとユーザープロパティの両方で送っていますが、登録はユーザースコープ1つで足ります。同じ値を2つの枠で登録すると上限を無駄に使います。
  • ディメンションを「アーカイブ」しても枠はすぐ戻りません（48時間後）。上限が近いときは慎重に。

リアルタイムで絞り込む

カスタムディメンションは登録するとリアルタイムにはすぐ効きます。最大48時間かかるのは通常レポートと探索の方です。

  1. 比較を作る

    リアルタイムの概要の上部で「比較を追加」を押し、「新規作成」で ディメンション「プラン」、条件「完全一致」、値「pro」を選んで適用します。すべてのカードが「すべてのユーザー」と「プラン = pro」の2系列になります。

  2. ユーザープロパティ別のカードを見る

    「アクティブユーザー」カードの見出しを「ユーザープロパティ別」に切り替え、「ユーザーパターン」を選ぶと、パターンごとの人数が出ます。テストサイトでパターンを切り替えてイベントを送ると、数秒で変わります。

見たいもの場所反映
ユーザープロパティ別の即時集計リアルタイムの概要の「アクティブユーザー: ユーザープロパティ別」カード数秒
絞り込んだ数値リアルタイムの「比較を追加」数秒
ユーザー個別のイベント履歴探索のユーザーエクスプローラ数時間
通常レポートでの集計レポートのエンゲージメント › イベント最大24〜48時間

リアルタイムは過去30分固定で、カードの種類も決まっています。任意のディメンションと指標を組み合わせたいときは Data API を使います（07章の realtime.html）。

探索で表を作る（翌日以降）

  1. 空白の探索を開く

    探索空白 を選びます。左の「変数」列でデータを選び、中央の「タブの設定」列で表の形を決める画面です。右上の期間は「今日」を含む範囲にします。

  2. ディメンションと指標を読み込む

    「ディメンション」の「＋」を押し、「カスタム」の中から「ボタン名」「プラン」を、「イベント」の中から「イベント名」を選んで「インポート」します。「指標」の「＋」からは「イベント数」「総ユーザー数」を入れます。

  3. 表を組み立てる

    手法自由形式
    行ボタン名
    列プラン
    値イベント数
    フィルタイベント名 完全一致 button_click

    「プランごとに、どのボタンが何回押されたか」の表になります。フィルタを外すと、button_click 以外のイベントの行が (not set) として出てくることも確かめてみてください。

  4. ユーザーエクスプローラで1人を追う

    探索ユーザー エクスプローラ を開くと、User-ID（またはアプリインスタンスID）ごとの行が出ます。22222222-bbbb-… をクリックすると、そのユーザーのイベントが時系列で見られます。

標準レポートで見る（翌日以降）

  1. イベントの詳細を開く

    レポートエンゲージメントイベント で button_click の行をクリックします。詳細ページに、登録したイベントスコープのディメンション（ボタン名・セクション）のカードが自動で出ます。

  2. 表にディメンションを足す

    レポート右上の鉛筆アイコン（レポートをカスタマイズ）から「ディメンション」を開き、「ディメンションを追加」で「プラン」を足して保存します。表の切り替えメニューからプラン別に見られるようになります。

キーイベントを設定する

キーイベント（旧称コンバージョン）は「事業上の成果」として特別に数えるイベントです。登録すると、集客レポートなどに「キーイベント数」が出るようになります。

  1. sign_up をキーイベントにする

    管理データの表示イベント で sign_up の行の星アイコン（キーイベントとしてマーク）をオンにします。まだ一度も届いていないイベント名は「キーイベント」画面の「新しいキーイベント」から名前で作れます。

出てこないときのチェックリスト

  • 登録前のデータを見ていないか。登録日時より前はすべて (not set) になります。
  • パラメータ名が完全一致しているか。buttonName と button_name は別物です。
  • 値が長すぎないか。100文字（ユーザープロパティは36文字）を超えると切り捨てられます。
  • そのイベントに値が付いているか。付いていないイベントの行は (not set) です。
  • しきい値が出ていないか。表の右上に注意マークが出ていれば、少人数のため非表示になっています。
  • 既定ディメンションに同じ名前がないか。method などは登録なしで既定の名前（「方法」など）で出ています。
  • まだ48時間たっていないか。探索と標準レポートは処理待ちのことがあります。

どうしても画面で見えない値は、BigQuery で直接確かめるのが確実です。06章で button_name を SQL で取り出します。
