05基礎BigQuery

BigQueryの基礎

BigQuery は Google のフルマネージド型・サーバーレスのデータウェアハウスです。MySQL などの RDBMS と同じ SQL で書けますが、設計思想と課金の仕組みがまったく違います。GA4 のデータを触る前に、ここを押さえておくと料金で失敗しません。

基本概念

列指向ストレージ

MySQL などの行指向DBは、1行分のデータをまとめて保存します。BigQuery は列単位で保存します。SELECT name FROM users なら name 列だけを読み、他の列には触りません。これが数十億行でも速く集計できる理由で、同時に「読んだ列の量で課金される」理由でもあります。

ストレージとコンピュートの分離

データの保存と処理が独立しています。サーバーの台数やインデックスを考える必要はなく、クエリを投げるとその都度 Google 側で必要な計算資源が割り当てられます。データが増えてもクエリ性能は落ちにくいです。

リソース階層

GCP プロジェクト      big-query-sample-492309   （課金と権限の単位）
└── データセット      analytics_324810718       （リージョンを持つ。テーブルの入れ物）
    └── テーブル      events_20260401           （列と行）
        └── カラム    event_name, event_params, …

テーブルは `プロジェクトID.データセット名.テーブル名` とバッククォートで囲んで参照します。データセットにはリージョン（このリポジトリは asia-northeast1）があり、作成後は変えられません。別リージョンのテーブル同士は結合できません。

料金とコストの守り方

項目料金（オンデマンド）無料枠
クエリスキャンしたデータ量に応じて $6.25 / TiB毎月 1 TiB
ストレージ保存量に応じて課金（90日更新がないと自動で半額）毎月 10 GiB
ストリーミング挿入GA4 のストリーミングエクスポートなどで発生なし

金額は改定されることがあるので、最新は公式の料金ページで確認してください。学習用途の GA4 データなら、無料枠の中に収まるのが普通です。

コストを守る5つの習慣

  1. SELECT * を使わない。全列をスキャンします。必要な列だけ書きます。
  2. LIMIT では安くならない。LIMIT 10 を付けても、スキャン量は全件分です。中身を見たいだけなら、テーブルの「プレビュー」タブ（無料）を使います。
  3. 日付で絞る。GA4 のテーブルは日付ごとに分かれているので、_TABLE_SUFFIX で範囲を絞るとスキャン量が減ります。
  4. 実行前に処理量を見る。エディタ右上に「このクエリを実行すると 12.3 MB が処理されます」と出ます（ドライラン）。
  5. 上限を掛ける。BigQuery の左メニューの下にある 設定ユーザー設定処理されるクエリのバイト数を制限する で「デフォルトのを変更する」にチェックを入れ、上限をバイト数で入れて保存します（1GB なら 1000000000）。自分がコンソールで実行するすべてのクエリに効き、超えるクエリは料金がかからずに失敗します。プロジェクト全体に掛けたいときは、GCP の「IAM と管理 › 割り当て」で BigQuery の1日あたりのクエリ使用量に上限を設定します。
BigQuery サンドボックス

課金アカウントを紐づけなくても、サンドボックスとして無料枠の範囲で使えます。ただしテーブルが60日で自動削除され、GA4 のストリーミングエクスポートは使えません。

基本操作

データセットとテーブルを作る

CREATE SCHEMA IF NOT EXISTS `big-query-sample-492309.tutorial`
OPTIONS (location = 'asia-northeast1');

CREATE TABLE IF NOT EXISTS `big-query-sample-492309.tutorial.employees` (
  employee_id INT64,
  name        STRING,
  department  STRING,
  salary      INT64
);

BigQuery の SQL では、データセットのことを SCHEMA と書きます。

データを挿入する

小規模なら INSERT INTO で SQL から直接挿入できます。本番の大量データには向かないので、GCS からのバッチロードや Storage Write API を使います。

INSERT INTO `tutorial.employees` (employee_id, name, department, salary)
VALUES
  (1, '田中太郎', 'エンジニアリング', 6000000),
  (2, '佐藤花子', 'マーケティング', 5200000);

クエリを実行する

ワイルドカード events_* で、日付ごとに分かれた複数のテーブルをまとめてクエリできます。例は「直近7日」にしてあるので、そのまま実行できます。_TABLE_SUFFIX は * に当たる部分の文字列で、これで日付範囲を絞るとスキャン量が減ります。

SELECT event_name, COUNT(*) AS cnt
FROM `big-query-sample-492309.analytics_324810718.events_*`
WHERE _TABLE_SUFFIX BETWEEN FORMAT_DATE('%Y%m%d', DATE_SUB(CURRENT_DATE('Asia/Tokyo'), INTERVAL 7 DAY))
                        AND FORMAT_DATE('%Y%m%d', CURRENT_DATE('Asia/Tokyo'))
GROUP BY event_name
ORDER BY cnt DESC;

エクスポート

  • コンソールから: クエリ結果の「結果を保存」から CSV をダウンロード（1GB以下）。
  • SQL で: EXPORT DATA OPTIONS (uri = 'gs://…/*.csv', format = 'CSV') AS (SELECT …)
  • bq コマンドで: bq extract --destination_format CSV dataset.table gs://…

インポート

  • コンソールから: データセットの「テーブルを作成」で「アップロード」を選ぶ（10MB以下）。
  • SQL で: LOAD DATA INTO dataset.table FROM FILES (format = 'CSV', uris = ['gs://…'])
  • bq コマンドで: bq load --source_format=CSV --autodetect dataset.table ./file.csv

BigQuery 特有の SQL

GA4 のデータを扱うときに必ず出てくるものだけを挙げます。

STRUCT と ARRAY

BigQuery の列は、入れ子の構造（STRUCT）や配列（ARRAY）を持てます。GA4 の device.category は STRUCT、event_params は「STRUCT の ARRAY」です。STRUCT はドットで中に入れますが、ARRAY は UNNEST で行に展開しないと中が見られません。

STRUCT: ドットで取り出す

SELECT device.category, geo.city
FROM `big-query-sample-492309.analytics_324810718.events_*`
WHERE _TABLE_SUFFIX = FORMAT_DATE('%Y%m%d', DATE_SUB(CURRENT_DATE('Asia/Tokyo'), INTERVAL 1 DAY));  -- 昨日

ARRAY: UNNEST で展開する

1つのイベントが、パラメータの数だけ行に増えます。

SELECT event_name, p.key, p.value.string_value
FROM `big-query-sample-492309.analytics_324810718.events_*`, UNNEST(event_params) AS p
WHERE _TABLE_SUFFIX = FORMAT_DATE('%Y%m%d', DATE_SUB(CURRENT_DATE('Asia/Tokyo'), INTERVAL 1 DAY));  -- 昨日

よく使う関数

関数用途例
PARSE_DATE文字列の日付を DATE にPARSE_DATE('%Y%m%d', event_date)
TIMESTAMP_MICROSマイクロ秒の整数を TIMESTAMP にTIMESTAMP_MICROS(event_timestamp)
DATETIME(ts, tz)タイムゾーンを指定して日時にDATETIME(TIMESTAMP_MICROS(event_timestamp), 'Asia/Tokyo')
FORMAT_DATEDATE を文字列に（_TABLE_SUFFIX 用）FORMAT_DATE('%Y%m%d', CURRENT_DATE('Asia/Tokyo'))
SAFE_CAST / SAFE_DIVIDE失敗時にエラーではなく NULL を返すSAFE_DIVIDE(purchases, sessions)
COUNTIF条件付きの件数COUNTIF(event_name = 'purchase')
QUALIFYウィンドウ関数の結果で絞るQUALIFY ROW_NUMBER() OVER (PARTITION BY user_pseudo_id ORDER BY event_timestamp) = 1

シャーディングとパーティション

GA4 のエクスポートは日付ごとに別テーブル（events_20260401, events_20260402 …）を作ります。これをシャーディングと呼び、ワイルドカードと _TABLE_SUFFIX で扱います。自分でテーブルを作るときは、1つのテーブルを日付列で区切るパーティション分割テーブルの方が推奨されています。
