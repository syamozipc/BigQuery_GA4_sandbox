可視化とAPI

集めたデータを人に見せる方法は、GA4 の画面のほかに3つあります。Looker Studio、BigQuery API で作る BigQuery ダッシュボード（dashboard.html）、GA4 Data API で作るリアルタイム ダッシュボード（realtime.html）です。それぞれの仕組みと向き不向きを整理します。

どれを使うか

方法データの鮮度自由度費用向いている用途
GA4 の画面数秒〜48時間低い（登録したディメンションのみ）無料日々の確認
Looker Studio + GA4 コネクタGA4 画面と同じ中無料SQL なしで社内向けレポート
Looker Studio + BigQuery翌日（ストリーミングなら数分）高い（SQL で何でも）BigQuery のスキャン分生データを使った社内ダッシュボード
BigQuery ダッシュボード（dashboard.html）同上最も高い（画面も自作）同上業務システムへの組み込み
リアルタイム ダッシュボード（realtime.html）過去30分中（GA4 の集計値を任意の組み合わせで）無料（クォータあり）リアルタイムの監視

Looker Studio

Google が提供する無料の BI ツールです。BigQuery と直接つながり、ドラッグ＆ドロップでグラフや表を作れます。このリポジトリのレポートはこちらです。

  1. データソースをつなぐ

    作成レポート でデータソースに「BigQuery」を選び、プロジェクト・データセット・テーブルを指定します。GA4 のテーブルなら「マイプロジェクト」から events_* 相当の日付分割テーブルを選べます。

  2. カスタムクエリで期間を連動させる

    「カスタムクエリ」を選ぶと SQL を書けます。「期間パラメータを有効にする」にチェックすると、レポートの期間指定が @DS_START_DATE と @DS_END_DATE（YYYYMMDD 形式の文字列）として渡されます。

    SELECT
  PARSE_DATE('%Y%m%d', event_date) AS day,
  event_name,
  (SELECT value.string_value FROM UNNEST(user_properties) WHERE key = 'plan') AS plan,
  COUNT(*) AS events,
  COUNT(DISTINCT user_pseudo_id) AS users
FROM `big-query-sample-492309.analytics_324810718.events_*`
WHERE _TABLE_SUFFIX BETWEEN @DS_START_DATE AND @DS_END_DATE
GROUP BY day, event_name, plan

    期間を絞らないクエリは、レポートを開くたびに全期間をスキャンします。必ず期間パラメータか、06章の集計済みテーブルを使います。

  3. 共有する

    URL で共有でき、Google アカウント単位でアクセスを制御できます。データソースの「データの認証情報」を「オーナー」にすると、閲覧者に BigQuery の権限がなくても見られます。

ブラウザから Google API を呼ぶ準備

dashboard.html と realtime.html は、サーバーを持たずにブラウザから直接 Google の API を呼んでいます。認証は Google Identity Services（GIS）の OAuth 2.0 で、ログインした人の権限でデータを読みます。

  1. OAuth クライアントを作る

    GCP コンソールの API とサービス認証情報OAuth クライアント ID を作成 で、種類を「ウェブ アプリケーション」にします。「承認済みの JavaScript 生成元」に https://syamozipc.github.io と、ローカル用の http://localhost:8000 を入れます。

  2. 同意画面とスコープを設定する

    OAuth 同意画面に、使う API のスコープを追加します。公開ステータスが「テスト」の間は、テストユーザーに登録したアカウントしかログインできません。

    ページ有効にする APIスコープ
    dashboard.htmlBigQuery APIhttps://www.googleapis.com/auth/bigquery.readonly
    realtime.htmlGoogle Analytics Data APIhttps://www.googleapis.com/auth/analytics.readonly

  3. ページ側の流れ

    どちらのページも同じ流れです。

    1. 「Google でログイン」ボタンで ID トークンを受け取り、名前とアイコンを表示する。
    2. google.accounts.oauth2.initTokenClient でスコープを指定し、アクセストークンを要求する。
    3. API 呼び出しの Authorization: Bearer <アクセストークン> ヘッダーに付ける。
    const client = google.accounts.oauth2.initTokenClient({
  client_id: CLIENT_ID,
  scope: "https://www.googleapis.com/auth/bigquery.readonly",
  callback: (resp) => {
    accessToken = resp.access_token;
    fetchAll();
  },
});
client.requestAccessToken();
ブラウザ直叩きの限界

ログインした人の権限で動くので、BigQuery や GA4 の閲覧権限がない人には何も表示されません。誰でも見られる画面にしたいときは、サーバー側でサービスアカウントを使って API を呼び、結果だけを返す構成にします。

BigQuery ダッシュボード（BigQuery API）

BigQuery ダッシュボード（dashboard.html）は、BigQuery REST API の jobs.query に SQL を投げ、返ってきた行を Chart.js でグラフにしています。表示しているのは日次テーブルのデータで、ストリーミングが有効なら今日の分（events_intraday_）も含められます。

画面のカードは06章のレシピに対応しています。送信元の比較（gtag.js と GTM）、プラン別、イベント別、パラメータの値、ファネル、ユーザーの行動履歴です。各カードの「実行した SQL を見る」で、実際に投げた SQL と処理量が確かめられます。

const res = await fetch(
  `https://bigquery.googleapis.com/bigquery/v2/projects/${PROJECT_ID}/queries`,
  {
    method: "POST",
    headers: { Authorization: "Bearer " + accessToken, "Content-Type": "application/json" },
    body: JSON.stringify({ query: sql, useLegacySql: false, timeoutMs: 30000 }),
  },
);
const data = await res.json();
// data.rows = [{ f: [{ v: "12" }, { v: "34" }] }, …]  列の順に値が入る

レスポンスの行は rows[i].f[j].v という形で、値はすべて文字列です。数値として使うときは Number() で変換します。KPI のセッション数は、06章のレシピ4と同じ SQL で数えています。

リアルタイム ダッシュボード（GA4 Data API）

リアルタイム ダッシュボード（realtime.html）では、ページ別・イベント別・プラン別・パターン別・ユーザー別の表を出し、ユーザーを選ぶとすべてのカードがその人に絞られます。各カードの「送ったリクエストを見る」でリクエストの中身が、画面上部で1日のクォータの残りが確かめられます。

GA4 の画面のリアルタイムは、過去30分固定・カード固定で、任意のディメンションと指標の組み合わせやセグメントは使えません。Data API の runRealtimeReport を直接呼ぶと、過去30分のデータを好きな組み合わせで取れます。無料です。

// ユーザースコープのカスタムディメンションは customUser: を付けて参照する
const res = await fetch(
  `https://analyticsdata.googleapis.com/v1beta/properties/${PROPERTY_ID}:runRealtimeReport`,
  {
    method: "POST",
    headers: { Authorization: "Bearer " + accessToken, "Content-Type": "application/json" },
    body: JSON.stringify({
      dimensions: [{ name: "customUser:app_user_id" }],
      metrics: [{ name: "activeUsers" }, { name: "eventCount" }],
      dimensionFilter: {
        filter: {
          fieldName: "customUser:app_user_id",
          stringFilter: { matchType: "EXACT", value: uuid },
        },
      },
    }),
  },
);
  • リアルタイムの API で使えるカスタムディメンションは、ユーザースコープ（customUser:）だけです。イベントスコープ（customEvent:button_name など）は、通常のレポート用の runReport で使います。どちらも02章で登録済みであることが前提です。
  • minutesAgo ディメンション（"0"〜"29"）を使うと、分単位の推移が取れます。
  • レスポンスは rows[i].dimensionValues[j].value と rows[i].metricValues[j].value の形です。

ユーザー単位で使うときの制約

  • しきい値: Google シグナル有効時、少人数のデータはプライバシー保護で非表示になります。
  • (other) へのまとめ: UUID のように値の種類が多いディメンションは、行数の上限を超えると (other) に集約されます。
  • クォータ: 標準プロパティには1日あたりのトークン上限があります。短い間隔でのポーリングは要注意です。realtime.html の自動更新は30秒間隔です。
  • 認証: ブラウザ直叩きはログインした人の権限になります。

集計や傾向を見るなら API で十分です。特定ユーザーの行動履歴を業務画面に正確に出したいなら、しきい値と (other) で欠けるので、BigQuery エクスポートか自社DBの方が確実です。

ひと通り終えたら

  • 自分のサービスで「計測したいこと」を10個書き出し、それぞれ推奨イベント・カスタムイベントのどちらで、どのパラメータを付けるかを表にしてみる（01章）。
  • その表のうち、dataLayer で送るものとクリックトリガーで拾うものを分ける（03章）。
  • BigQuery で答えたい問いを1つ決め、06章のレシピを組み合わせて SQL を書く。
